-Problems
+CPU load 100% when watch video on different computer.

Mục tiêu: dựng luồng login → access token (body) + refresh token (HttpOnly cookie) → mọi request gắn access token qua Authorization header → 401 do access token hết hạn thì tự động gọi /auth/refresh (dựa vào cookie) lấy access token mới rồi retry → nếu refresh cũng fail thì logout về trang login.

 Ngoài phạm vi (note lại, không làm trong plan này): endpoint /auth/register (chưa tồn tại ở BE), field role/permission trên User FE (model quyền thật là permission-code qua AuthorizationService, không phải enum), NoOpPasswordEncoder (plaintext password — rủi ro có sẵn, sửa sẽ vỡ dữ liệu seed cũ), refresh-token rotation/blacklist (v1 dùng refresh token tĩnh tới khi hết hạn 7 ngày).

 Backend changes

 1. application.yml + config/dev/config.yml + config/prd/config.yml
 Thêm cấu hình CORS origin cho phép và cookie secure-flag theo profile (hiện dev/prd config.yml đang trống):
 app:
   cors:
     allowed-origins: http://localhost:3000   # prd: điền domain FE thật
 request:
   cookie:
     refresh-cookie-name: MOVIE_REFRESH-TOKEN  # đã có sẵn
     secure: false                              # prd: true
     same-site: Lax
 Gợi ý (không bắt buộc): rút ngắn jwt.access-token-expiration-time từ 36000 (10h) xuống ví dụ 900 (15 phút) để silent-refresh thật sự có ý nghĩa — báo lại cho bạn quyết định giá trị cuối.

 2. common/util/JwtUtil.java
 Sửa generateRefreshToken(String) → generateRefreshToken(UserDetailsImpl user) để nhúng thêm claim id (đồng bộ với generateAccessToken), tránh phải query lại user theo username khi refresh.

 3. auth/service/AuthenService.java + AuthenServiceImpl.java
 - Thêm method refresh(String refreshToken).
 - login(): gọi thêm jwtUtil.generateRefreshToken(user), trả về access token + refresh token + user thật (map từ User entity: id, username, email, displayName — bỏ các field ảo avatar/signature/role/phone/tenantId/func vì User entity không có các cột này).
 - refresh(refreshToken): jwtUtil.validateToken(token, true) → nếu fail ném InvalidRefreshTokenException (class mới, nhỏ) để controller bắt riêng và trả 401 thật (KHÔNG dùng BusinessException vì sẽ bị RestControllerExceptionAdvice ép về 200). Nếu hợp lệ: lấy id claim → load User → sinh access token mới (giữ nguyên refresh token, không rotate ở v1).
 - Response DTO mới AuthResponse { accessToken, user } (thay LoginResponse), tách riêng refresh token (không bao giờ nằm trong JSON body).

 4. auth/controller/AuthController.java
 - Đổi mapping: POST /auth/login, POST /auth/logout, thêm POST /auth/refresh.
 - login/refresh nhận thêm HttpServletResponse response để set cookie qua helper dùng org.springframework.http.ResponseCookie (httpOnly(true), secure/sameSite đọc từ config, path("/api/movie"), maxAge(refresh-token-expiration-time)).
 - refresh đọc cookie qua @CookieValue(name = "${request.cookie.refresh-cookie-name}", required = false); bắt InvalidRefreshTokenException → ResponseEntity.status(401).build() trực tiếp (bỏ qua advice chung).
 - logout đọc cookie tương tự, clear cookie (maxAge(0)), giữ response body đơn giản như hiện tại.

 5. common/config/SecurityConfig.java
 - Thay .cors(cors -> cors.disable()) bằng .cors(cors -> cors.configurationSource(...)) — bean CorsConfigurationSource đọc app.cors.allowed-origins, allowCredentials(true), allow header Authorization/Content-Type, allow method GET/POST/PUT/DELETE/OPTIONS.
 - Cập nhật permitAll() matcher: thay "/login" bằng "/auth/login", "/auth/refresh", "/auth/logout".

 6. common/filter/JwtAuthenticationFilter.java
 Mở rộng danh sách bypass (hiện đang check prefix /swagger-ui, /v3/api-docs, /login) để thêm /auth/login, /auth/refresh, /auth/logout — các endpoint này không cần access token hợp lệ để vào (refresh tự validate refresh-token riêng bên trong).

 7. common/interceptor/AuthorizationInterceptor.java
 Bỏ đoạn set thủ công Access-Control-Allow-Origin/Access-Control-Allow-Credentials (đang duplicate/conflict với CORS config tập trung mới ở bước 5).

 8. config/default/config.yml
 Cập nhật interceptor.authorization.exclude-paths: thay /login bằng /auth/login,/auth/refresh,/auth/logout.

 Frontend changes

 1. src/types/api.ts
 AuthResponse = { accessToken: string; user: User }; User rút gọn còn {id, username, email, displayName} khớp dữ liệu thật từ BE (bỏ firstName/lastName/role/teamId/bio — field demo cũ không có backing data).

 2. src/lib/token-store.ts (mới)
 Zustand store giữ accessToken chỉ trong memory (không persist — refresh token trong HttpOnly cookie mới là nguồn "nhớ" phiên qua reload, đúng như yêu cầu). Cùng pattern với useNotifications (getState() dùng được ngoài React, cần cho axios interceptor).

 3. src/lib/refresh-token.ts (mới)
 Axios instance riêng (không đi qua interceptor của api) gọi POST /auth/refresh với withCredentials: true. Có dedup: nếu đang có 1 refresh in-flight, các lời gọi sau chờ chung promise đó (tránh nhiều 401 song song trigger nhiều lần refresh).

 4. src/lib/api-client.ts
 - Request interceptor: gắn thêm Authorization: Bearer <token> từ token-store (nếu có).
 - Response interceptor: khi 401 và request gốc chưa retry và không phải chính request refresh/login/logout → gọi refreshAccessToken() → set token mới → retry request gốc (_retry flag để tránh loop). Refresh thất bại → clear token-store → giữ logic redirect login hiện có (tiện sửa luôn bug nhỏ đang có: dòng searchParams.get('redirectTo') đang đọc từ new URLSearchParams() rỗng thay vì window.location.search).

 5. src/lib/auth.tsx
 - loginInputSchema: đổi email → username (khớp BE thật).
 - loginFn: lưu accessToken vào token-store trước khi trả user.
 - userFn = gọi refreshAccessToken(): thành công → lưu token + trả user; thất bại vì "không có cookie/hết hạn" (case bình thường khi chưa đăng nhập) → trả null (không throw) để AuthLoader coi là "chưa đăng nhập" thay vì lỗi.
 - logoutFn: gọi POST /auth/logout rồi clear token-store.

 6. src/app/provider.tsx
 Truyền renderError thật cho AuthLoader (UI fallback tối thiểu) thay vì mặc định JSON.stringify(error) — phòng trường hợp lỗi mạng thật (không phải "chưa đăng nhập") không còn hiện {} nữa.

 7. src/features/auth/components/login-form.tsx
 Đổi field email → username (label + input, schema đã đổi ở bước 5).
